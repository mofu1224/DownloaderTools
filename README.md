# DownloaderTools

動画・音声・画像をローカルに保存するWebアプリです。URLをキューに登録すると順番にダウンロードします。中断したキューは再開でき、保存済みのファイルは上書きしません。

現行版は **0.1.0の検証候補** です。Windows x64で検証しています。設計上のmacOS対応・24時間運転などは未検証で、製品全体のリリース判定は完了していません。本体の再配布ライセンスも未指定です。

## リポジトリのクローンと起動

Windows x64では、PowerShellで次のコマンドを実行します。初回セットアップ後は `Start-DownloaderTools.bat` をダブルクリックするだけで起動できます。

```powershell
git clone https://github.com/mofu1224/DownloaderTools.git
cd DownloaderTools
.\Start-DownloaderTools.bat
```

対応環境は **Windows x64** です。`Start-DownloaderTools.bat` を実行すると、必要なローカル環境をこのフォルダ内に自動で準備してからブラウザが開きます。言語ランタイム・依存・FFmpeg等の手動導入は不要です。

初回セットアップ・環境の再構築は次のコマンドでも実行できます。グローバルpip・npm・PATH・Python登録を変更せず、`runtime/`・`.venv/`・`.cache/`へ配置します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/bootstrap.ps1
```

- 同梱の実行環境とキャッシュが揃ったコピーでは、通信せずに準備できます。`-Offline` を付けると通信を禁止した状態で再構築を検証できます。
- クローン直後は、初回に固定版のuv・Python・Node・FFmpegと依存を検証付きで取得します（目安 合計1〜2GB、回線により数分〜十数分）。再開・再実行は安全で、取得済みの配布物は`.cache/distributions`から再利用します。
- フロントの静的資産はビルド済みを同梱しています。`frontend/`を変更した場合のみ`-BuildFrontend`で再ビルドします。

ブラウザを開かず起動する場合:

```powershell
.\.venv\Scripts\python.exe -m downloader_tools --no-browser
```

- 待受は`127.0.0.1:8765`〜`:8784`。空いているポートを自動選択します。
- 認証は起動リンクのワンタイムトークンからセッションCookieへ交換します。通常起動では起動スクリプトがリンクを開きます。
- 終了はサーバーのコンソールで`Ctrl+C`。ブラウザを閉じてもダウンロードは続きます。
- 移設を検出した場合、起動スクリプトがlock済み依存から仮想環境を再生成します。`runtime/`と`.cache/`が揃っていれば通信は不要で、欠けている場合だけ取得します。
- 設定・DB・Cookie・ログは`data/`、メディアは既定で`downloads/`です。`data/`と`runtime/`は稼働中のクラウド同期対象に置かないでください。

## 使い方

1. 「ダウンロード」で動画／画像を選び、URLを1行ずつ入力します。
2. 保存形式・解像度・Cookie・保存先を選んで「キューに追加」。プレイリストは明示的に有効にします。
3. 一時停止・再開・キャンセル・詳細確認はSourceごとのボタンから操作できます。
4. 「履歴」で結果とログを確認し、必要なSourceだけ新規再試行できます。
5. 「認証」でNetscape TXT / JSON Cookieを取り込みます。更新は新しい不変版として取り込んで選択します。
6. 「設定」で並列数、保存先、toolset、バックアップを管理します。

既定の同時実行は全体2件、動画1件、画像1件、同一provider 1件です。後処理を起動し得るSourceも全体1件に制限します。画像の「画像・サイト内動画」もこの枠を使用します。

MP4はH.264 / AAC版を優先します。提供されていない場合は、取得可能な映像・音声から必要なストリームだけをMP4互換形式へ変換します（変換には処理時間がかかり、再エンコードによる画質・音質への影響があります）。MP3は明示的な音声変換です。元形式は元のコーデックを保持します。

新しく保存する動画・音声・画像の保存先は、`プラットフォーム名/投稿者名/タイトル.拡張子`です。例: `YouTube/投稿者/動画タイトル.mp4`、`X/投稿者/投稿本文.png`。拡張子は選択した形式または元画像の形式になります。

- サイトごとの投稿者情報の違いを吸収し、不明なら`投稿者不明`、タイトルがなければ投稿IDまたは識別子で補います。汎用抽出・直リンクではドメイン名をプラットフォーム名に使います。
- 禁止文字・予約名・長すぎる名前を安全化します。同名投稿・複数画像・異なる品質の衝突時だけ短い識別子を付け、既存ファイルを上書きしません。保存済みのファイルは登録済みパスを再利用します。
- 動画・音声は、サイトが提供するサムネイルを対応形式へ埋め込みます。元形式のWebMはコーデックを保持したままMKVへ詰め替えます。画像自体へのサムネイル埋め込みは行いません。
- 再開時も新しく取得する項目には埋め込みます。公開済みファイルと実体を共有する候補は後処理で変更しません。サムネイルがない場合や埋め込み非対応の形式は、メディアのみ保存します。
- 画像の「画像・サイト内動画」では、サイトが配布するZIP添付もCRC検証後にZIPのまま保存します。自動展開は行いません。暗号化・破損、展開量4GiB超・1万項目超のZIPは検証エラーとして表示します。「画像のみ」には適用しません。
- 「画像のみ」では、動画・音声・ZIP等の対象外添付を正常スキップとして数え、次の画像へ進みます。判別できるものは転送前に除外し、拡張子が不明な動画やZIPも内容確認後にスキップします。対象外だけのSourceも正常完了になり、再開・復旧で同じ項目を二重計上しません。画像自体の破損は検証エラーとして扱います。

サイトの抽出・子ページへの巡回・アルバム処理はyt-dlp / gallery-dlへ委ねます。アプリ側に対応サイトの許可リストはなく、入れ子のメタデータも共通処理で読み取ります。一時保存はサイト標準の階層・タイトル・投稿内連番に依存しない固定長の識別名を使い、完成後に上記の階層へ配置します。ID欠損・同名添付・番号のリセットでも別のファイルを誤って同一扱いしません。署名付きURLなどが変化した場合、同一コンテンツを別項目として取得することがあります。

## ポータブルな配布・移設

- このフォルダは丸ごとコピーして別の場所（空白・日本語を含むパス、別ドライブも可）へ置いても、`Start-DownloaderTools.bat`の実行だけで動きます。仮想環境は元の絶対パスを保持するため、移設を検出すると`runtime/`の同梱物と`.cache/`から仮想環境とtoolsetを作り直します。設定・DB・メディアは作り直しで消えません。
- 別のカレントディレクトリから起動しても、各スクリプトとアプリは自身の場所を基準に動作します（`Start-DownloaderTools.bat`は自身のフォルダへ移動してから起動します）。
- `data/`（設定・DB・Cookie本文）・`downloads/`（保存メディア）・`.cache/`（検証用キャッシュ・ログ）・`.venv/`・`runtime/`は`.gitignore`で追跡対象から除外し、クローン先の初回起動で新規作成します。既に追跡されたファイルはignoreだけでは除外されないため、公開前には追跡一覧も確認してください。Cookie本文は`data/credentials/`にのみ保存されます。
- 次のコマンドで、公開予定のファイルだけを日本語・空白入りの別パスへコピーし、PATHから開発端末のpython/node/uvを除いた状態・別カレントディレクトリ・通信禁止の条件で、準備と起動を検証できます。

```powershell
.\.venv\Scripts\python.exe scripts/verify_portable.py
```

同梱・取得する外部ソフトウェアのライセンス表示は[`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md)を参照してください。

## 保存・復旧

- ファイルは保存先内の非公開作業領域へ取得し、画像／ffprobe検証、DBのpublish intent、ハードリンクによる非上書き公開、Artifact登録の順に確定します。
- 公開後も非終端Sourceの作業リンクを保持します。同じSourceを再開すると、エンジンの非上書き判定で完成済み項目の再転送を抑制します。終端確定後は完成品と同じ実体の作業リンクだけを整理します。メディアの二重コピーにはなりません。
- 既存の別Sourceと同じ成果物は、内容を照合してから同一扱いします。サイトをまたぐ転送前の完全なスキップは保証しません。
- 一時停止／キャンセルで公開済みのメディアは消しません。部分ファイルも保持します。
- 異常終了後は所有プロセスと未確定保存を照合します。所有権やファイル内容を確認できない場合は「確認が必要」で保留します。
- 実行時間上限は既定6時間。手動一時停止・キュー待ちを除き、Attempt間で累積します。
- エンジンと子プロセスの出力・CPU・読み書きを監視し、5分間すべて動きがない場合は停止して最大2回自動再開します。部分ファイルと確定済みの保存結果を再利用し、一時停止・キャンセル・累積実行上限を優先します。動画変換など無出力でもCPUやI/Oが動く処理は継続します。
- 保存先はローカルNTFSをWindowsで検証しています。別ボリュームを登録した場合もリンク・ロックを試験します。ネットワーク共有は非対応です。

### 詳細ログ

Sourceの「詳細」を開くと、実行ログを約1秒ごとに追記表示します。時刻、Attempt、開始・転送進捗・ファイル取得・15秒ごとの稼働確認・終了コード・停止理由・自動再開回数を確認できます。画像取得の転送量と速度もキューに表示します。

ログは`data/logs/<Source ID>.log`、スケジューラー自体の例外は`data/logs/scheduler.log`へ記録します。URLやCookie・認証値は伏せ、1ログ5MiB／全体100MiBの上限を維持します。

## ツールの更新・切戻し

設定画面の「公式安定版を取得・検証」は、公式PyPIのyt-dlp / gallery-dlを別環境へ取得します。依存をハッシュ付きrequirementsに固定し、CLIと構造出力契約を検証してから新規受付の有効版を切り替えます。

旧Sourceは元のtoolsetを使い続けます。有効版の選択で旧版へ戻せます。FFmpeg・Nodeの更新は、アプリ停止中のセットアップで配布物を検証し、新しいtoolsetを構築する運用です。旧toolset内の実行ファイルは差し替えません。

Python依存は`uv.lock`、フロント依存は`frontend/package-lock.json`、各toolsetは`manifest.json`と`requirements.txt`に固定されます。SQLite公式配布は公式のSHA3-256で検証し、Node・FFmpegは配布元のSHA-256で検証します。各実行バイナリのSHA-256もtoolsetへ記録します。

初回取得の検証値は`scripts/runtime-lock.json`とbootstrap内のuv固定値で管理します。FFmpegの取得URLは配布元で更新されるため、内容が固定値と違えば停止します。その場合はハッシュ検査を外さず、保守側で公式配布物を確認して固定値・契約試験を更新してください。

## バックアップ・復元

設定画面からSQLite Backup APIによるバックアップを`data/backups/`へ作成できます。Cookie本文とメディアは含めません。元URLは含まれるため、バックアップも非公開データとして扱ってください。

アプリ停止中に復元:

```powershell
.\.venv\Scripts\python.exe -m downloader_tools --restore "E:\backup\app.sqlite3"
```

復元元を一時DBへコピーし、整合性・スキーマ版・必要なテーブル・設定を検査してから現在のDBを置換します。復元前のDBも`data/backups/before-restore-*.sqlite3`へ退避し、復元後の未完了Sourceは保留します。現在のDB自身、未知の版、無関係なSQLiteファイルは拒否します。失敗した場合は現在のDBを置換せず、一時DBを片付けます。

### 本体の更新・移動・削除

- 更新前にアプリを終了し、現在の本体と`data/`、必要な`downloads/`を別の非公開フォルダへ退避してください。DBバックアップだけではCookie本文とメディアは復元できません。
- 新しい版を別フォルダへクローンし、停止中の`data/`と`downloads/`を移して起動します。`runtime/`と`.cache/`も移せば取得済みの環境を再利用できます。外部保存先は移動対象外なので、設定で場所を確認してください。
- 現行DBはスキーマv2です。v1は退避後に更新します。未知の新しい版は拒否します。旧アプリへ戻す場合は、旧アプリに対応する退避一式を使ってください。新DBを旧アプリで開けるとは限りません。
- ログ・バックアップ・途中ファイルは自動で全削除しません。フォルダ全体を削除すると、内部のCookie・履歴・保存メディアも失われます。必要なデータを退避してから本体を削除してください。

### データと通信

元URL・履歴・設定はDB、Cookie本文は`data/credentials/`へ保存します。Cookieは平文ファイルをOSのアクセス権で保護する方式で、暗号化保管ではありません。ログではURL・認証値を伏せますが、ファイル名等が含まれる場合があるため、ログやバックアップの共有前にも内容を確認してください。バックアップは自動削除されません。

ダウンロード時はエンジンが指定サイトと関連CDN等へ通信し、選択したCookieをサイトへの認証に使用します。初回セットアップとツール更新は配布元へ通信します。アプリ独自の利用解析送信は実装していません。ローカルIPの入力拒否はネットワーク隔離ではなく、DNSやリダイレクト先をすべて遮断する機能ではありません。自分が信頼でき、取得権限のあるURLを入力してください。

### 困ったとき

| 症状 | 対処 |
|---|---|
| 起動リンクが使用済み、接続できない | 接続済みのブラウザを使うか、アプリを終了・再起動して新しい起動リンクで開きます |
| 初回取得の通信・ハッシュ検証に失敗 | 接続と空き容量を確認して起動を再実行します。検証を無効にしたり、`data/`を削除したりしないでください |
| Cookieの形式エラー | Netscape TXTまたは対応JSONで再度書き出します。失敗した内容は新規登録されません |
| 空き容量不足・保存先を使用できない | ローカルNTFSの空き容量・アクセス権・他の起動プロセスを確認します。途中ファイルを無断で削除しないでください |
| 「確認が必要」で保留 | 詳細ログと診断を確認し、原因を解消して再開します。所有プロセスが不明な状態でロックを削除しないでください |

不具合は [GitHub Issues](https://github.com/mofu1224/DownloaderTools/issues) に、版・OS・再現操作・表示されたエラーを添えて報告してください。Cookie本文・起動トークン・秘密付きURLは添付しないでください。

## 開発・検証

初回は`bootstrap.ps1 -BuildFrontend`を実行し、固定依存を準備します。次の入口でLint・型検査・フロントビルド・全pytest・代表ベンチマークを時間制限付きでまとめて実行できます。結果と終了コードは`.cache/verification/run-*/results.json`、詳細は同じフォルダのログへ出力し、どれかが失敗すると終了コード1を返します。ブラウザ試験にはMicrosoft Edgeが必要です。

```powershell
.\.venv\Scripts\python.exe scripts/verify.py
```

```powershell
.\.venv\Scripts\python.exe -m pytest --basetemp=.cache/tests
.\.venv\Scripts\ruff.exe check src tests scripts
.\.venv\Scripts\ruff.exe format --check src tests scripts
.\.venv\Scripts\pyright.exe --pythonpath .venv/Scripts/python.exe
.\runtime\uv.exe pip check --python .venv/Scripts/python.exe
```

フロントの型検査・ビルド:

```powershell
$env:PATH = "$PWD/runtime/build-tools/node-v24.14.1-win-x64;$env:PATH"
.\runtime\build-tools\node-v24.14.1-win-x64\npm.cmd run build --prefix frontend
```

ブラウザ試験はWindowsのMicrosoft Edgeをheadlessで使用します。テスト用データは一時フォルダ内に分離し、外部サイトや利用者のCookieを使用しません。実エンジン試験はローカルHTTP fixtureから動画・画像を取得します。

可搬性の検証（配布用コピーを別パスへ作り、オフライン準備・別CWD・非グローバルPATHで起動確認）:

```powershell
.\.venv\Scripts\python.exe scripts/verify_portable.py
```

同梱物のない初回取得を試す場合は`--source-only --timeout 600`を付けます。検証用コピーは`.cache/`内に作成し、終了時に削除します。実データを含む作業フォルダを検証先に指定しないでください。

依存アドバイザリ照合:

```powershell
.\.venv\Scripts\python.exe scripts/audit_dependencies.py
```

クローン直後に相当する状態で初回取得・全検証・起動を確認する場合:

```powershell
.\.venv\Scripts\python.exe scripts/verify_portable.py --source-only --checks --timeout 600
```

ソース・ビルド済み静的資産・固定定義・文書だけを別パスへコピーし、`data/`・`downloads/`・`runtime/`・仮想環境・キャッシュを引き継がずに準備します。`--checks`はフロントの開発依存も固定版から取得し、コピー内で全検証を実行します（初回通信あり）。入力ファイル一覧とSHA-256、結果は`.cache/clone-checks-*/`へ保存し、検証用コピーは終了時に削除します。

このスクリプトは作業ツリーから配布対象をコピーします。公開コミットそのものを検証する場合は、別フォルダへクローンし、その中でセットアップと検証を実行してください。

## 対応範囲

- Windows x64のセットアップと実行を検証対象としています。
- 同梱物が揃ったコピーは、通信なしで移設先の準備と起動ができます。取得直後（同梱物なし）は初回に固定版を取得するため通信が必要です。
- macOS向けの停止・ロック・フォルダ起動処理、`scripts/start.sh`は用意していますが、macOSのネイティブ配布物・SQLite差替え・移設は未検証です。Windowsの実行環境をそのままmacOSへコピーして起動する構成ではありません。
- 期間指定はサイト別の日時・並び順契約が未検証のため、受付時に明示的に拒否します。
- 拡張子の固定リストで画像・動画を制限せず、Pillowまたはffprobeで内容を検証します（TIFF / BMPなども対象）。両方で内容を確認できない形式は公開を保留します。「画像のみ」では既知の動画・音声を取得前に除外し、未知の形式も保存前に確認します。
- 総件数不明のときは割合やETAを推測しません。取得0件で理由を確定できない場合も成功扱いしません。
- 初期版はSource全体の再試行です。投稿内の失敗項目をID指定して再試行するUIは提供していません。
- LAN公開、クラウド同期、DRM解除、メディアの自動削除は提供しません。

## 再利用しているソフトウェア

FastAPI / Starlette、SQLite、uv、yt-dlp、gallery-dl、FFmpeg、Node.js、Pillow、psutil、portalocker、pywin32、TypeScript / Viteを使用しています。サイト抽出・メディア転送・変換・OSロックはこれらを再利用し、アプリ独自の部分をキュー・状態・保存確定・UIに限定しています。

配布時には各同梱物のライセンス・著作権表示・ソース提供条件を確認してください。とくにgallery-dlとFFmpegのGPL条件が適用される配布物を含みます。
